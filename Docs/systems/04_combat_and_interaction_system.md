# Combat and Interaction System

_Simple third-person pressure, not hack-and-slash._

## Purpose

Combat exists to add pressure to interpretation and restoration. It should not become the dominant game.

## Complexity Target

Combat should be simple, closer to Elder Scrolls-style input complexity than action-game mastery.

Possible core inputs:

- Move
- Jump
- Left click: simple attack / light strike
- Right click: block / ward / channel / cleanse
- Interact: restore / examine / activate
- Optional focus/inspect mode

## Design Intent

The player should win because they understood the situation, not because they executed a complex combo.

Good combat question:

> Can I hold off pressure long enough to cleanse the right object or activate the correct structure?

Bad combat question:

> Can I kill fifty enemies efficiently?

## Enemy/Threat Design

Threats should be readable and tied to night rules.

Examples:

- a creature vulnerable only in restored light
- corruption that must be cleansed while minor enemies interrupt
- invisible threat revealed by mirror restoration
- possessed object that must be disrupted, then purified
- direct attacker used sparingly as pressure

## Avoid

- deep weapon trees
- combo systems
- stamina-heavy soulslike combat unless later deliberately chosen
- loot-driven combat builds
- hack-and-slash enemy volume
- making combat the primary progression axis
